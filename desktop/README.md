# Music Remover для компьютера

Приложение для macOS (позже и для Windows): перетаскиваете видео или аудио, получаете копию без фоновой музыки. Голос остаётся.
Для видео можно ещё размывать женщин и наготу (галочка внизу окна), а готовый файл прослушать «до / после» (кнопка «Сравнить»).
Работает без интернета, на видеокарте. Модель та же, что в расширении: UVR MDX-Net «Kim Vocal 2».

## Как пользоваться

1. Откройте **Music Remover**.
2. Перетащите файлы в окно (или нажмите «выберите файлы»). Можно сразу несколько, можно целую папку.
   Ещё варианты: перетащить файлы на иконку в Dock или выбрать «Открыть с помощью → Music Remover» в Finder.
3. Готовый файл появится **рядом с оригиналом** с припиской «(без музыки)», например `Лекция (без музыки).mp4`.
   Папку для готовых файлов можно сменить внизу окна.

Что происходит с файлом:
- **Видео не перекодируется**: картинка копируется побайтно, качество не меняется. Заменяется только звук.
- Формат сохраняется: MP4 → MP4, MKV → MKV, MP3 → MP3, WAV → WAV и т. д.
  WMV и WMA записываются в MKV и M4A соответственно (в исходный формат FFmpeg пишет плохо).
- Сохраняются субтитры, обложка MP3, главы, метаданные, язык звуковой дорожки, частота дискретизации (вплоть до 96 кГц) и моно/стерео.
- Объёмный звук 5.1 сводится в стерео: модель работает со стерео.
- Длина файла не ограничена: звук обрабатывается кусками, память не растёт.

- **Ползунок «Убирать музыку»** (внизу окна, по умолчанию 100 %): очищенный голос смешивается с оригиналом в этой пропорции. На тестовом тоне: оригинал −21,1 дБ, 100 % → −72,2 дБ, 50 % → −27,1 дБ, 0 % → −21,1 дБ. Действует на файлы, добавленные после изменения.
- **Там, где музыки нет, играет оригинал**: отрезки по 0,5 с, на которых убранная часть тише оригинала более чем на 30 дБ (чистая речь), берутся из самого файла, с переходом 30 мс (порт `passthrough` из расширения).
- **Самотест видеокарты.** CoreML / DirectML могут молча считать неверно, поэтому при первой загрузке модель прогоняется на фиксированном правдоподобном сигнале на GPU и на CPU, и выходы сравниваются (порог 10 %). При расхождении работает процессор, об этом написано внизу окна. Прохождение запоминается на месяц (по размеру файла модели, движку и версии ORT), так что CPU-прогон (несколько секунд) делается один раз. На M1 Pro CoreML расходится с CPU на 0,12 %. Отключить: `mr-cli --no-selftest`.

Интерфейс на русском и английском (переключатель RU/EN). Приписка к имени файла зависит от языка: «без музыки» / «no music».

## Плеер: смотреть без музыки, звук вровень с картинкой

Живой режим (ниже) отстаёт на ~0,4 с (раньше 1,8 с): поток нельзя ускорить, его слышно только по ходу воспроизведения, а картинку чужого приложения мы не задерживаем. Для **файла** задержки нет: ссылка «смотрите сразу, без ожидания» на главном экране (или `--play ФАЙЛ` в командной строке) открывает файл в плеере приложения. Музыка убирается **с опережением** (в ~17 раз быстрее реального времени, готово около 10 с вперёд), звук играет приложение, а картинка идёт в беззвучном видеоэлементе окна и следует за позицией звука (при расхождении больше 0,25 с он подтягивается, меньше — скорость слегка подстраивается). Перемотка и пауза работают (после перемотки звук появляется примерно через 0,4 с), ползунок «Убирать музыку» действует почти сразу (звук пересчитывается с текущего места). Движок: `core/src/player.rs`, команды `player_*` в `app/src/player.rs`. Включение плеера выключает живой режим (оба играли бы).

Проверено: часы плеера против реального времени (`core/tests/player.rs`, запускается вручную `-- --ignored`: позиция идёт со скоростью реального времени с точностью 0,25 с, готово ≥ 5 с вперёд, пауза держит позицию, перемотка → звук за 0,4 с, смена силы без скачка, конец файла); в настоящем окне со слайд-шоу (картинки меняются на 4-й и 8-й секунде) картинка совпала с позицией звука до секунды, в том числе после перемотки. **Не проверено на слух** (звук в тестах — тихий синтетический тон, который модель убирает) и на длинных файлах. Картинку показывает системный видеоэлемент окна: он играет MP4/MOV/M4V с H.264/HEVC и WebM, MKV и AVI не показывает (тогда играет только звук, написано в окне). Размытия в плеере нет, только музыка. Смену устройства вывода плеер на ходу не отслеживает.

## Прослушивание «до / после»

У готового файла есть кнопка «Сравнить»: приложение вырезает один и тот же отрывок (30 с, место выбирается ползунком «Участок файла») из оригинала и из результата, и можно переключаться между «Оригинал» и «Без музыки» на ходу, звук идёт синхронно. Отрывки временные (кэш приложения, чистятся при запуске). Файл к этому моменту уже сохранён: это сравнение после обработки, а не предварительный просмотр до записи. Работает с любым форматом, который читает FFmpeg (отрывок переводится в WAV). Движок: `core/src/preview.rs`, команды `prepare_preview`, `preview_bytes`, `clear_preview`. В настоящем окне проверено открытие панели и загрузка отрывков (длина 0:12 у 12-секундного файла); воспроизведение проверено в браузерной демо-странице на беззвучном отрывке (кнопка, время, переключение, пауза), в самом окне звук не пускался.

## Размытие женщин и наготы в видео

Галочка «Размывать женщин и наготу в видео» (можно вместе с «Убирать музыку» или одну). Работает для файлов, не для живого режима. Это сокращённый перенос логики расширения (`core/src/blur/`):

1. **Просмотр:** 4 кадра в секунду (до 640 px), NudeNet (нагота и лица; на CoreML ~25 мс на кадр), по каждому лицу InsightFace genderage (две обрезки головы, как в расширении).
2. **Решение:** нагота ≥ 0,5 на одном кадре, 0,3–0,5 на трёх кадрах за 1,5 с; голый торс строже (0,65). Женщина: лица сцепляются в людей по положению **внутри одной сцены** (смена кадра находится по миниатюре 32×18), человек считается женщиной при средней вероятности ≥ 0,4 и двух кадрах ≥ 0,3 (одиночный кадр: ≥ 0,5). Голова и тело размываются на всех её кадрах, плюс 0,5 с до и после.
3. **Запись:** кадры читаются целиком, области размываются (три прохода box blur), картинка кодируется заново аппаратным H.264 (VideoToolbox) с битрейтом исходника; звук, субтитры, главы и метаданные копируются как есть. Если включена и музыка, сначала делается файл без музыки (скрытый временный файл рядом, потом он удаляется).

Имя результата: `(размыто)` или `(без музыки, размыто)`; контейнер сохраняется, WebM/WMV/FLV дают MKV (в WebM нельзя H.264).

Проверено: на 12-секундном слайд-шоу из реальных портретов (женщина, мужчина, пейзаж) женщина размыта целиком (голова и тело), мужчина и пейзаж не тронуты, звук скопирован. То же через собранное приложение с настоящими кнопками (`core/tests/blur.rs`; портреты не в репозитории, тест пропускается без `MR_PHOTOS`). На настоящих фильмах, интервью и быстром движении **не проверялось**.

**Чего нет по сравнению с расширением:** второй взгляд с увеличением на мелкие лица, MobileCLIP («женщины, которых не нашли»: танцовщицы издалека, тёмная съёмка), подсказка по высоте голоса, решение «женщина есть в сцене → скрыта вся сцена» (здесь только её собственные кадры ± 0,5 с), чувствительность мягко / строго, заливка вместо размытия. Женщина без видимого лица, издалека или со спины, скорее всего **не найдётся**. Видео 10-бит и HDR сводятся к 8-битному SDR, переменная частота кадров приводится к постоянной. Нет самотеста видеокарты для моделей размытия (в отличие от модели звука). Модель genderage только для некоммерческого использования, NudeNet под AGPL-3.0 (таблица лицензий в корневом README).

## Требования

- macOS 14+ на Apple Silicon (на Intel будет работать на процессоре, медленнее).
- **FFmpeg встроен** в приложение (`Resources/bin`: LGPL-сборка без x264/x265, статическая, только системные библиотеки). Homebrew не нужен. Проверено: запущенное приложение вызывает `Contents/Resources/bin/ffmpeg`.

## Сборка

```bash
cd desktop
npm install            # Tauri CLI
npm test               # юнит-тесты + полный прогон на сгенерированном видео
npm run build          # → target/release/bundle/macos/Music Remover.app и .dmg
```

Нужны Rust (`brew install rustup && rustup default stable`), Node, модели `../models/Kim_Vocal_2.onnx`, `nudenet-320n.onnx`, `genderage.onnx`
(`npm run fetch-model` в корне репозитория) и встраиваемый FFmpeg: `brew install lame opus mpg123 pkg-config`, затем `sh scripts/build-ffmpeg.sh`
(скачивает официальные исходники FFmpeg 9.0.2, сверяет SHA-256 с формулой Homebrew, собирает `vendor/ffmpeg/ffmpeg` и `ffprobe`, около 10 минут; без `--force` готовое не пересобирает).
Для тестов хватает и обычного `brew install ffmpeg`.

Консольная утилита для проверки без интерфейса:

```bash
cargo run -p mr-core --release --bin mr-cli -- [--cpu] [--suffix "без музыки"] файл1.mp4 файл2.mp3
```

## Живой режим: что уже измерено

Модель принимает окно ровно из 256 кадров (5,9 с), поэтому окно не укоротить (проверено: onnxruntime отклоняет другие размеры). Но для потока это не нужно: модель точна везде, кроме последних 87 мс окна, поэтому каждые `hop` секунд запускается окно, заканчивающееся на самом свежем звуке, и берётся только его последний отрезок (`core/src/live.rs`, без захвата звука).

| Что | Результат |
|---|---|
| Совпадение с обычной нарезкой, реальная запись с речью и музыкой (20 с, `/tmp/mr/real_mix.wav`, происхождение не записано), шаг 1 с / 0,5 с | **27,6 / 26,3 дБ** (то есть тот же звук: модель сама даёт ~21 дБ) |
| То же, синтетика (голос + аккорд), SDR к истинному голосу | 24,3 дБ при любом шаге, как у нарезки |
| Тест `core/tests/live.rs` на CoreML: потоковый движок против нарезки | 28,3 дБ |
| Один прогон модели на CoreML (M1 Pro) | ≤ 0,25 с, то есть ~25 % видеокарты при шаге 1 с |
| Задержка | шаг + 0,09 с + прогон: около **1,4 с** при шаге 1 с, около 0,9 с при 0,5 с (нагрузка ~50 %) |

Остаётся то, чего здесь нет: захват и вывод системного звука (macOS: Core Audio tap, 14.2+, разрешение на запись звука; Windows: WASAPI loopback), звук отстаёт от картинки на всю задержку (системное приложение не может задержать видео: подходит для аудио, а для видео работает расширение, которое читает вперёд), и проверка на разной музыке (здесь только синтетика и одна реальная запись).

## Живой режим на macOS: командная строка `mr-live`

Захват системного звука готов и проверен (macOS 14.2+, Core Audio process tap; `core/src/mac/tap.m`, `core/src/capture.rs`). Tap забирает всё, что играет система, кроме самого процесса; звук, которым Mac играет сам, глушится (`CATapMuted`), и слышно только обработанное. Цепочка: tap → ресемплинг в 44,1 кГц → скользящее окно (`live.rs`) → ресемплинг обратно → устройство вывода. Если ничего не играет (цифровая тишина), модель не запускается.

```bash
cargo build -p mr-core --release --bin mr-live
./target/release/mr-live [--hop 1] [--strength 0-100] [--no-passthrough] [--keep-original]
                         [--seconds N] [--record out.wav] [--record-input in.wav] [--no-playback] [--capture-test]
```

При первом запуске macOS спросит разрешение «Запись системного звука» (для собранного `.app` текст запроса задан в `app/Info.plist`, `NSAudioCaptureUsageDescription`). Без разрешения tap отдаёт тишину. `--record` пишет обработанный звук в WAV (для проверки без прослушивания), `--no-playback` ничего не играет, `--capture-test` только измеряет, что слышит tap.

Что проверено (M1 Pro, CoreML):

| Что | Результат |
|---|---|
| Tap слышит то, что играет система, и только это | тишина → ровно 0, звук → сигнал (`core/tests/capture.rs`, запускается вручную: `-- --ignored`) |
| Захваченный вход против исходного файла | корреляция 0,999, SNR 24–30 дБ (ограничено 16 бит записи) |
| Вся цепочка (проигрыватель → tap → окно → запись) против обычной обработки того же файла | **26–33 дБ** по секундам, без дрейфа по времени (запускалось 4 раза, см. ниже) |
| Захват 48 кГц → модель 44,1 кГц (ресемплер) | то же, 22–33 дБ |
| Свой вывод не попадает обратно в захват (воспроизведение с `--strength 0`, то есть задержанного оригинала) | SNR входа не упал: обратной связи нет |
| Нагрузка (короткое окно, шаг 0,1 с) | самый медленный прогон модели 35–60 мс за шаг 0,1 с (~35 % GPU); буфер вывода 150–250 мс, **0 пропусков** в 5 прогонах по 35 с |
| Задержка | шаг 0,1 с + 0,09 с + прогон + запас 0,15 с: **около 0,4 с** (было 1,8 с: шаг 1 с, прогон 0,3 с, запас 0,4 с) |

Что нашлось по дороге:
- Заявленная в формате tap частота (48 кГц) не всегда равна той, с которой приходят блоки: блоки идут по часам устройства (44,1 кГц, если устройство на нём). Берётся частота агрегатного устройства. Пока это не было исправлено, звук растягивался и цепочка не совпадала с эталоном совсем.
- Частота устройства может меняться на ходу (проигрыватель переключает её под свой файл). `mr-live` опрашивает её 3 раза в секунду и пересоздаёт ресемплер; **такое переключение в живую не проверено** (для проверки пришлось бы менять системную настройку звука).
- «Провалы качества» в одном из первых прогонов оказались артефактом измерения. Шесть повторных прогонов на синтетической речи с аккордом (вход и выход записывались) показали, что сходство с файлом по секундам скачет от 17 до 38 дБ из-за дробной задержки между файлом и захватом: сравнение шло с выравниванием на целое число отсчётов. Если подогнать 7-отводный фильтр (он поглощает дробную задержку), захваченный вход совпадает с файлом на 42–80 дБ в каждой секунде, а голос на выходе: 48–76 дБ там, где нет музыки (играет оригинал), и 23–26 дБ с аккордом (это качество самой модели), во всех шести прогонах одинаково. Громкость системы не менялась (усиление 1,00). Исходный прогон с провалом я заново проверить не могу (данных не осталось), так что это объяснение, а не доказательство для него.

### Живой режим в окне приложения

В собранном и подписанном приложении кнопка «Включить» нажата в настоящем окне: карточка показала «Работает · звук идёт с задержкой 1,8 с · … сейчас ничего не играет», запрос разрешения на запись звука не появился. Звук через неё в этом прогоне не пускался (качество проверено раньше тестами). Над областью перетаскивания есть карточка «Слушать без музыки» с кнопкой «Включить / Выключить» (только на macOS). Пока режим включён, она показывает этап (запуск, загрузка нейросети, подключение к звуку), потом задержку звука и занятость видеокарты, а также «сейчас ничего не играет», если звука нет. Ползунок «Убирать музыку» внизу окна работает и для живого режима, и меняется на ходу. Если видеокарта не прошла самотест, это тоже написано. При выходе из приложения tap отпускается, и системный звук снова слышен как обычно.

Устройство: `core/src/live_session.rs` (сессия на отдельном потоке: вывод, модель, захват; `start`, `stats`, `set_strength`, `stop`), команды Tauri `live_start`, `live_stop`, `live_status`, `live_set_strength` в `app/src/live.rs`, карточка в `ui/`. `mr-live` теперь тоже работает поверх этой сессии.

Проверено: сессия целиком в `core/tests/live_session.rs` (запускается вручную, `-- --ignored`; тон как «музыка»: при 100 % выход −50 дБ от входа, после смены ползунка на 0 % на ходу тон проходит целиком), на синтетической речи с аккордом против истинного голоса 25,9 дБ без аккорда и 22,6 дБ с ним, интерфейс в браузерной демо-странице (оба языка). **Окно Tauri**: собранное приложение запускается и показывает карточку с кнопкой «Включить» (то есть команда `live_status` в настоящей среде отвечает); саму кнопку я в окне не нажимал. Разрешение на запись звука для собранного `.app` не проверялось: текст запроса лежит в `app/Info.plist`, а подпись приложения (нужна для стабильной записи в «Конфиденциальности») не сделана.

Смена устройства вывода (наушники, AirPods): сессия опрашивает устройство по умолчанию 3 раза в секунду и при смене заново открывает вывод и tap (его часы — это устройство вывода); на время переключения системный звук слышен как обычно. Проверена принудительным перезапуском на том же устройстве (`handle.restart_audio()`, тест `live_session`: после перезапуска сессия работает, тон по-прежнему убирается, ползунок действует); **настоящую смену устройства я физически не проверял**.

**Устройство вывода можно выбрать** (`--device ИМЯ`, `--list-devices` в `mr-live`; выпадающий список «Куда играть» в окне, виден, если устройств больше одного). Захват тогда работает на часах выбранного устройства (агрегатное устройство tap строится на нём), а tap слышит всё, что играет система, на какое бы устройство оно ни шло. Неизвестное имя даёт ошибку, а не тихий откат. Проверено на единственном устройстве этого Mac: выбор по имени работает (`core/tests/live_session.rs`), а с несколькими устройствами не пробовалось.

### Windows

Код есть и **компилируется** под `x86_64-pc-windows-msvc` (ядро, `mr-live`), но на Windows ни разу не запускался. Захват: WASAPI loopback через `cpal` (`core/src/capture_win.rs`). Loopback слышит всё, что играет устройство, в том числе наш собственный вывод, поэтому слушать нужно не то устройство, куда мы играем: установите виртуальный кабель (VB-CABLE), сделайте его устройством вывода в Windows, в окне выберите его в «Что слушать», а колонки или наушники в «Куда играть» (`--capture-device` и `--device` в `mr-live`). Windows не умеет глушить оригинал, поэтому без кабеля он звучал бы вместе с обработанным. Захват без кабеля с исключением собственного процесса (Windows 10 2004+ / 11) не сделан. Загрузка модели на DirectML и самотест на Windows тоже не проверялись.

Звук отстаёт от картинки на всю задержку (~0,4 с).

### Как задержка сократилась с 1,8 до 0,4 с

Сеть свёрточная по времени, поэтому те же веса работают на окне короче: `scripts/retime-onnx.py` пересохраняет `Kim_Vocal_2.onnx` с осью времени 32 кадра (0,74 с вместо 5,9 с), получается `Kim_Vocal_2.t32.onnx`. Прогон на CoreML 35 мс вместо 230 мс, поэтому модель можно гонять каждые 0,1 с, а не раз в секунду. Результат совпадает с длинным окном на 26–31 дБ на настоящих записях (`core/tests/live_short.rs`: закадровый голос под музыку и интервью), то есть звук тот же. Если короткой модели рядом нет, живой режим работает как раньше (шаг 1 с); на процессоре шаг не меньше 0,4 с. Уровень очереди вывода держится регулировкой скорости на доли процента: часы tap и устройства дрейфуют, и очередь иначе пустела (щелчок) или росла (лишняя задержка).

## Скрывать на экране (macOS)

Вторая карточка главного окна. Приложение смотрит на основной экран (ScreenCaptureKit, ~5 кадров в секунду, свои окна не видит) и накладывает размытие на женщин и наготу **в любом окне**: браузере, плеере, мессенджере. Размытие рисует система (окно без рамки поверх всего, клики проходят насквозь, внутри `NSVisualEffectView` с эффектом «за окном» и тёмной вуалью), поэтому оно следует за картинкой без нашей отрисовки, а наш захват его не видит.

Цепочка: кадр 1600 px → целиком и четырьмя перекрывающимися плитками (лицо в окне видео — десятки пикселей, а сеть видит 320) → NudeNet и классификатор пола → те же правила, что у файлов (`blur/timeline.rs`), но на скользящем окне в 2,5 с (`blur/live.rs`): женщина закрыта с первого кадра, где нашли лицо, и ещё 0,5 с после; слабая наготa нужна на трёх кадрах. Неподвижный экран заново не разбирается (кроме раза в 2 с). Код: `core/src/screen.rs`, `core/src/mac/screen.m`, команды `screen_*` в `app/src/screen.rs`. Нужно разрешение «Запись экрана» (Системные настройки → Конфиденциальность и безопасность); после выдачи приложение может потребовать перезапуска.

Для проверки: `MR_SCREEN_LOG=1` печатает в stderr, что нашлось на каждом разборе; `--overlay-demo` на 8 секунд показывает две заплатки (без захвата и без разрешения); `MR_OVERLAY_VISIBLE=1` делает заплатки видимыми для скриншотов (иначе окно скрыто от любого захвата). `MR_SCREEN_AUTOSTART=1` включает режим при запуске без клика.

Пределы: основной экран только (второй монитор не смотрится); задержка около 0,3 с (кадр может мелькнуть до закрытия); женщина без видимого лица (спиной) закрывается только если нашлась нагота; полноэкранные видео в отдельных Spaces и защищённое видео (DRM) не проверялись; нагрузка ~5 разборов по 10–20 мс в секунду на видеокарте.

## Что дальше

- **FFmpeg для Windows** (для macOS он встроен). `scripts/build-ffmpeg.sh` собирает только под macOS; libmp3lame и mpg123 берутся из Homebrew, и линкер предупреждает, что mpg123 собрана под более новую macOS (27), чем целевая 14: на самой macOS 14 запуск не проверялся.
- **Подпись и нотаризация** (Apple Developer, $99/год). Без неё при первом запуске macOS спросит подтверждение:
  правый клик → «Открыть». Скрипт готов: `scripts/sign-notarize.sh` (подпись .app с Hardened Runtime, `app/entitlements.plist`,
  DMG, `notarytool`, `stapler`), но **не запускался**: на этой машине нет сертификата. Права в `entitlements.plist` подобраны
  по аналогии с приложениями на ONNX Runtime; если подписанное приложение не стартует, смотрите Console.app.
  Для Windows подпись (Azure Trusted Signing или сертификат EV + `signtool`) не настроена.

Для запуска на этом же Mac есть `scripts/sign-dev.sh`: он подписывает собранный `.app` вашим собственным сертификатом «Apple Development» (выбирает именно его, сертификаты Distribution и Developer ID не берёт). Подпись даёт приложению стабильный идентификатор `app.musicremover.desktop`, и macOS не спрашивает разрешение «Запись системного звука» заново после каждой сборки (у неподписанной сборки идентификатор менялся, `music_remover-<хэш>`). Проверено: подписанное приложение запускается (hardened runtime, `NSAudioCaptureUsageDescription` попадает в `Info.plist`, модель внутри). Скрипт подписывает и встроенные `ffmpeg` / `ffprobe` (изнутри наружу). Для раздачи другим людям это не годится: нужны сертификат Developer ID Application и нотаризация (`sign-notarize.sh`), их в связке ключей нет (есть только Apple Development и Apple Distribution).
- **Windows**: код уже рассчитан на это (DirectML, пути, скрытие консоли FFmpeg), но сборка и проверка на Windows ещё не делались.
- «Скрывать на экране» проверено на портретах в Просмотре и на видео в QuickTime без звука (неподвижная женщина закрыта головой и телом и остаётся закрытой; 40 с интервью с мужчинами: ни одной заплатки; разбор кадра 65–70 мс).
